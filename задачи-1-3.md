## 1. Зафиксировать границы MVP

### 1.1. Направление стажировок
**[ПРЕДЛОЖЕНИЕ]** Backend-разработка (Python).

Обоснование: у команды есть реальный опыт (freelance ML/DS + разработка ботов), поэтому легко самим проверить корректность тестовых вопросов (пункт 4.6 плана) и не привлекать внешнего эксперта. Альтернативы, если не подходит: Data Analysis / ML-инженерия — тоже близко к текущему опыту команды.

### 1.2. Конкретный пользователь
**[ПРЕДЛОЖЕНИЕ]** Студент 2–4 курса технической специальности, который готовится к первой стажировке в Backend-разработке на Python и не уверен, какие из требований вакансии он уже закрывает.

### 1.3. Способ ввода
Пользователь вставляет текст описания стажировки прямо в чат бота (копирует с сайта вакансии). Ссылку можно приложить дополнительно как источник — но автоматическое чтение сайта по ссылке не реализуем в MVP (задача на будущее).

### 1.4. Основной сценарий
Описание → определение требований → готовый тест → проверка → результат.

### 1.5. Проверяемые навыки
**[ПРЕДЛОЖЕНИЕ]** 4 ключевых навыка для Backend/Python-стажировок:
1. Python (основы языка, стандартная библиотека)
2. SQL (базовые запросы, JOIN, агрегация)
3. Git (базовый флоу: commit, branch, merge, конфликты)
4. HTTP/REST (методы, статус-коды, структура запроса/ответа)

### 1.6. Границы разработки (Won't Have на этот раз)
- Поиск вакансий (пользователь сам приносит описание)
- Личные кабинеты работодателей
- Мини-приложение (весь сценарий — в чат-боте)
- Обучение ML-модели с нуля (используем готовый сервис/API для извлечения навыков)

### 1.7. Доска и ответственные
**Готово** — используем GitHub Projects, колонки «Нужно сделать / В работе / На проверке / Готово».

## 2. Подтвердить проблему и определить пользу

### 2.1–2.2. Интервью со студентами и затруднения

1. Расскажи о последнем разе, когда ты откликался на стажировку/вакансию — как ты понял, что описание тебе подходит?
2. Как ты оцениваешь, готов ли ты к требованиям из описания вакансии?
3. Было ли такое, что ты не знал, подтягивать конкретную тему или нет, перед откликом? Что делал в итоге?
4. Какими материалами/сайтами пользуешься, чтобы проверить свои знания перед стажировкой?
5. Что бы тебе реально помогло в этой ситуации?

**1. Расскажи о последнем разе, когда ты откликался на стажировку/вакансию — как ты понял, что описание тебе подходит?**

Последний раз я смотрел вакансию по своему направлению и в первую очередь сравнивал требования с тем, что уже знаю. Обычно смотрю на технологии, языки программирования и основные навыки, которые указаны в описании. Если большая часть требований мне знакома и я понимаю хотя бы примерно, о чём идёт речь, то считаю, что вакансия мне подходит и можно откликаться.

При этом иногда описание бывает достаточно общим, и не всегда понятно, насколько глубоко нужно знать конкретную технологию.

**2. Как ты оцениваешь, готов ли ты к требованиям из описания вакансии?**

Обычно просто прохожусь по списку требований и субъективно оцениваю каждое: знаю хорошо, знаю поверхностно или практически не знаю. Но какой-то объективной проверки обычно нет.

Например, я могу написать, что знаю Python или SQL, потому что работал с ними на учебных проектах, но не всегда понимаю, соответствует ли мой уровень тому, что ожидают на стажировке.

**3. Было ли такое, что ты не знал, подтягивать конкретную тему или нет, перед откликом? Что делал в итоге?**

Да, такое было. Если в вакансии есть несколько технологий или тем, с которыми я знаком поверхностно, бывает непонятно, насколько они вообще важны для этой конкретной стажировки.

Обычно в такой ситуации я просто ищу информацию по этой теме, смотрю несколько вопросов или тестов и уже по ощущениям решаю, нужно ли её повторить. Иногда из-за этого трачу время на темы, которые в итоге не особо нужны.

**4. Какими материалами/сайтами пользуешься, чтобы проверить свои знания перед стажировкой?**

Обычно использую документацию, YouTube, статьи и различные сайты с тестами или задачами. Ещё могу посмотреть типовые вопросы на собеседованиях и попробовать решить несколько задач.

Проблема в том, что приходится самому сопоставлять всё это с требованиями конкретной вакансии. Единого места, где я могу вставить требования и получить проверку именно по ним, у меня нет.

**5. Что бы тебе реально помогло в этой ситуации?**

Было бы удобно вставить описание стажировки и сразу получить список требований, которые там проверяются. После этого пройти небольшой тест именно по этим темам и увидеть, что я уже знаю, а что стоит подтянуть.

Особенно полезно было бы, если бы после теста показывались конкретные темы, в которых есть пробелы, и материалы для их повторения. Тогда было бы понятнее, что делать дальше, а не просто получать результат вроде «ты готов» или «ты не готов».


### 2.3. Текущий путь студента (As Is)

| Шаг | Что делает | Где теряется |

| Находит вакансию/стажировку | HH.ru, Telegram-каналы, вузовские рассылки | — |
| Читает требования | Текст описания | Формулировки размыты («опыт с базами данных» — какими конкретно?) |
| Оценивает свою готовность | На глаз, без объективной проверки | Переоценивает или недооценивает себя |
| Ищет, что подтянуть | Гуглит, спрашивает у знакомых | Нет чёткого списка тем именно под эту вакансию |

### 2.4. Существующие способы решения (2–3 аналога)
1. **LeetCode / Stepik / курсы на YouTube** — дают общую подготовку, но не привязаны к конкретному описанию вакансии
2. **Тестовые задания от самого работодателя** — приходят уже после отклика, поздно для самопроверки
3. **Советы знакомых/старшекурсников** — неструктурированно, зависит от того, кого знаешь

**Дополнительная польза бота:** мгновенная привязка конкретного описания вакансии к проверке конкретных навыков — до отклика, а не после.

### 2.5. Формулировка проблемы одним предложением
Студент находит интересную стажировку, но не понимает, какие требования уже выполняет и что ему нужно подтянуть.

### 2.6. Показатели для проверки
- Доля пользователей, завершивших тест до конца
- Время прохождения теста
- Понятность результата и следующего шага (проверяется опросом после теста: «было ли понятно, что делать дальше?»)

### 2.7. Гипотезы vs результаты
До проверки — писать «ожидаем, что...». После пилота на студентах (задача 8.9–8.10 плана) — заменить на «по данным N участников...».

## 3. Спроектировать диалог

### 3.1. Приветствие
```
Привет! Я помогу понять, готов ли ты к стажировке.

Пришли текст описания вакансии (просто скопируй и вставь) —
я найду ключевые требования и предложу короткий тест,
чтобы проверить, что ты уже знаешь, а что стоит подтянуть.

Сейчас поддерживаю направление: Backend-разработка (Python).
```

### 3.2. Сообщение после получения описания
```
Разобрал описание. Нашёл требования по темам:
• Python
• SQL
• Git

Хочешь пройти короткий тест (10 вопросов, ~7 минут),
чтобы понять, что уже закрыто, а что стоит подтянуть?

[Начать тест] [Не сейчас]
```

### 3.3. Формат заданий
Вопросы с вариантами ответа (кнопки в MAX).

### 3.4. Сообщения во время теста
```
Вопрос 3 из 10 — тема: SQL

Какой оператор используется для объединения строк
из двух таблиц по условию?

[JOIN] [MERGE] [UNION] [LINK]
```

После ответа — короткое подтверждение без раскрытия правильности («Принято, следующий вопрос») до финального результата, чтобы не портить объективность оставшихся вопросов.

### 3.5. Успешный результат
```
Готово! По проверенным темам (Python, SQL, Git) —
ты справился уверенно.

Рекомендую откликнуться на эту стажировку.

Хочешь пройти тест по другому описанию?
```

### 3.6. Результат с пробелами
```
Готово! Вот что получилось:

✅ Python — сильно
✅ Git — уверенно
⚠️ SQL — есть пробелы (3 из 4 вопросов)

По SQL стоит подтянуть тему JOIN и агрегатные функции.
Вот короткий материал: [ссылка]
Попробуй это упражнение: [упражнение]

Пройти тест ещё раз после подготовки?
```

### 3.7. Управление
- «Начать тест» — старт с нуля
- Если пользователь исчез посреди теста и вернулся — бот предлагает: «Продолжить с вопроса N?» или «Начать заново?»

### 3.8. Сообщения для стандартных ошибок
```
Пришла только ссылка:
"Пока не умею читать сайты по ссылке — скопируй, пожалуйста,
текст описания вакансии и пришли сюда."

Описание непонятно / слишком короткое:
"Не нашёл достаточно требований в этом тексте.
Пришли, пожалуйста, полное описание вакансии."

Направление не поддерживается:
"Пока умею проверять готовность только к Backend-стажировкам (Python).
Другие направления — в планах на будущее."
```
